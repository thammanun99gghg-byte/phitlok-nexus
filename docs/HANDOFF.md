## 1. โปรเจกต์นี้คืออะไร

เว็บแอปท่องเที่ยวพิษณุโลกสำหรับประกวด **All for One University 2569 · Software for Business & Tourism ("Make Me Money")**

**หน้าเว็บ 3 หน้า**

| หน้า | ไฟล์ | ใช้ทำอะไร |
|---|---|---|
| `/` | `public/index.html` + `public/js/landing.js` | หน้าแรก |
| `/app` | `public/app.html` + `public/app.js` | ตัวแอป มี 3 โหมด: นักท่องเที่ยว / ร้านและโรงแรม / ผู้บริหาร |
| `/credits` | `public/credits.html` | เครดิตและแหล่งอ้างอิง |

**เทคโนโลยี**
- Node 24 + Express 4 + `node:sqlite` (ไฟล์ DB อยู่ใน `data/`)
- หน้าเว็บเป็น ES modules ธรรมดา ไม่มี build step
- Three.js 0.160 จาก CDN, ไอคอน lucide@0.460.0 (ชื่อไอคอนต้องเป็น kebab-case)

**คำสั่ง**

```bash
npm start            # เซิร์ฟเวอร์พอร์ต 3000 (ตั้ง PORT / DATA_DIR ได้)
npm test             # smoke test (scripts/smoke-test.js) ใช้ DB ชั่วคราวของตัวเอง ตอนนี้ผ่าน 13/13
npm run qa:ui        # ตรวจหน้าจอด้วย Playwright (docs/qa/qa-ui.mjs) ต้องเปิดเซิร์ฟเวอร์ก่อน
npm run qa:e2e       # กดจริงทั้งระบบ 31 ขั้น (docs/qa/e2e.mjs) ค่าเริ่มต้นชี้ไปที่ BASE=http://localhost:3100
```

**รัน e2e บนฐานข้อมูลชั่วคราวเสมอ** เพราะชุดทดสอบกดซื้อจริง ถ้ารันบน DB หลัก ยอดในแดชบอร์ดจะเพี้ยน

```bash
DATA_DIR=/tmp/pn-e2e PORT=3100 node server.js   # เปิดไว้อีกหน้าต่างหนึ่ง
npm run qa:e2e
```

**ฐานข้อมูลรีเซ็ตเองอัตโนมัติ** เมื่อค่า `SCHEMA_VERSION` ใน `src/db.js` เปลี่ยน (ตอนนี้ = 25) ถ้าแก้ข้อมูลตั้งต้นใน `src/seed-data.js` หรือ `src/db.js` ให้เพิ่มเลขนี้ แล้วรีสตาร์ตเซิร์ฟเวอร์

## 4. งานแปลฝั่งนักท่องเที่ยวของ `/app` เป็น 6 ภาษา: เมนูและชำระเงินเสร็จแล้ว

**คำสั่งผู้ใช้:** "จัดการทำให้เรียบร้อยเลย" ให้แปลเส้นทางนักท่องเที่ยวทั้งหมด (แผนที่ → การ์ด → ส่องป้าย/เสียง → เมนู → ตะกร้า → ชำระเงิน → คูปอง/VIP) ให้ต่างชาติใช้ได้จริง

**การออกแบบ**
- **ที่เก็บคำแปล:** `public/js/i18n.js` มี 293 คีย์ แต่ละคีย์เป็น `[th, en, zh, ja, ko, fr]`
  - `t(key, vars, lang?)` แปลข้อความ (ระบุภาษาเฉพาะใบจองได้)
  - `applyStatic()` แปลแอตทริบิวต์ `data-i18n`, `data-i18n-aria`, `data-i18n-title`, `data-i18n-placeholder`
  - `formatDay()`, `builtYear()` (พ.ศ. สำหรับไทย, ค.ศ. สำหรับภาษาอื่น)
  - `errText(err)` (ข้อความ error จากเซิร์ฟเวอร์เป็นภาษาไทย ภาษาอื่นจึงแสดงข้อความกลางที่แปลแล้ว)
  - `unitName()` (แปลหน่วย ชาม/จาน/คืน ฯลฯ)
- **การเลือกภาษา:**
  - ภาษาที่เลือกเก็บใน localStorage `phitlok_lang` ใช้ร่วมกันทุกหน้า
  - `core.js` อ่านค่านี้เป็น `state.lang` และเรียก `setUiLang()`
  - เปลี่ยนภาษาด้วย `emit('lang:changed', lang)`
- **ปุ่มภาษาบนแถบบนของแอป:** `#lang-btn` + `#lang-menu` (ผูกใน `app.js` → `bindLanguagePicker`, `applyLanguageChrome`)
- **ส่วนที่คงเป็นภาษาไทยโดยตั้งใจ:**
  - หน้าร้าน (`#view-merchant`) และหน้าผู้บริหาร (`#view-admin`) มี `lang="th"` เพราะผู้ใช้คือพนักงานคนไทย

## 5. บั๊กและเรื่องที่รอผู้ใช้ตัดสินใจ (มาจากชุด VIP ที่ถูก stage ไว้)

แจ้งผู้ใช้ไปแล้ว **ยังไม่ได้แก้เพราะรอคำตอบ** ถ้าผู้ใช้สั่งให้แก้ ให้ทำตามนี้:

1. **ฟังเสียงฉบับเต็มฟรีด้วย `?vip=true`**
   - จุดเกิด: `server.js:260` (`clientVip`) และฝั่งหน้าเว็บ `lens.js` ที่ส่ง `&vip=true`
   - วิธีแก้: ลบทั้งสองจุด ให้เซิร์ฟเวอร์เชื่อแค่ `visitors.vip_until`
2. **ใครก็ได้ส่วนลด VIP 15%**
   - จุดเกิด: `src/commerce.js:235` (`|| body.vipActive === true`) และ `:379`
   - หน้าเว็บส่ง `vipActive` มาใน `menu.js` (`orderRequest`)
   - วิธีแก้: ใช้เฉพาะ `vip_until` ของผู้เยี่ยมชม
3. **สถานะ VIP เก็บใน localStorage `phitlok_vip_active`** ตั้งเองได้ (`site.js` → `isVipActive`)
   - หน้าต่าง VIP ที่เขียนใหม่ซิงก์ค่านี้กับเซิร์ฟเวอร์แล้ว แต่ `lens.js` และ `menu.js` ยังเชื่อค่านี้
   - วิธีแก้: ให้ทุกจุดใช้ `state.data.visitor.vip.active` จากเซิร์ฟเวอร์เท่านั้น
4. **ตัวเลขที่แต่งขึ้น "ร้านที่ยืนยันแล้ว 8 แห่ง"** (ข้อมูลจริงมี 0 จาก 8)
   - จุดเกิด: `server.js:354` (`activeCount || 8`), `landing.js:29` (`|| 8`), ค่าตั้งต้นใน `public/index.html` (`#hero-confirmed`)
   - การทดสอบ `scripts/smoke-test.js:115` และชื่อข้อทดสอบที่บรรทัด 158 ถูกแก้ให้บังคับว่าต้องเป็น 8
   - วิธีแก้: ใช้จำนวน `partner_status = 'confirmed'` จริง และแก้ข้อทดสอบ
5. **ปุ่มลอย `.scroll-cue`** (`#scroll-cue` ใน index/app) บังเนื้อหาและแผนที่ ควรเอาออกหรือย้ายให้ไม่บัง
6. **ป้าย "AI 6 ภาษา & OCR พร้อมใช้งาน"** แก้แล้วในงานนี้: ป้ายแสดงเฉพาะเมื่อ `ai.configured` และข้อทดสอบเปลี่ยนตามแล้ว

## 9. หลุมพรางที่เจอบนเครื่องนี้ (Windows)

- **Git Bash แปลงอาร์กิวเมนต์ที่ขึ้นต้นด้วย `/` เป็น path ของ Windows:** ใช้ `MSYS_NO_PATHCONV=1`
- **heredoc ที่มีเครื่องหมายคำพูดปนจะพัง:** เขียนสคริปต์เป็นไฟล์แล้วรันแทน
- **แก้ไฟล์ด้วย Python:** ใช้ `io.open(..., newline='')` เสมอ ไม่อย่างนั้นจะได้ CRLF
  - **regex ที่มี `\u0000-\u001f` ต้องเป็น raw string** เคยมีอักขระควบคุมจริงหลุดเข้าไฟล์จนต้องแก้
- **ชื่อไอคอน lucide:** ต้องมีอยู่จริงใน `scripts/data/lucide-0.460.0-icons.json` (`npm test` ตรวจให้)
- **เซิร์ฟเวอร์ส่ง header `Cross-Origin-Resource-Policy: same-origin`:** หน้าเปล่าแบบ `about:blank` จึงโหลดรูปจากเซิร์ฟเวอร์ไม่ได้ ให้เปิดหน้าจากเซิร์ฟเวอร์ก่อน
- **เว็บตั้ง `scroll-behavior: smooth`:** เวลาวัดตำแหน่งใน Playwright ให้ใช้ `scrollIntoView({ behavior: 'instant' })`
- **ข้อความ `GPU stall due to ReadPixels` ใน console:** มาจากไดรเวอร์ WebGL ของเครื่องทดสอบ ไม่ใช่บั๊ก (qa-ui.mjs ก็ไม่นับ)
