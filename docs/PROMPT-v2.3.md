# R1: ร้านอาหารต้องเป็นร้านจริง มีหน้าร้านชัด มีหมุดชัด และมีรูปครบ
**โครงข้อมูลใหม่ของทุกร้านและทุกที่พัก** (เก็บใน src/seed-data.js หรือย้ายไป `data/places.json` ก็ได้):
```
category: 'restaurant' | 'souvenir' | 'hotel' | 'landmark'
verified: false            // เป็น true ได้ก็ต่อเมื่อทีมตรวจครบทุกข้อในเช็กลิสต์
verification: {
  maps_url,                // https://www.google.com/maps/search/?api=1&query=LAT,LNG
  streetview_url,          // https://www.google.com/maps/@?api=1&map_action=pano&viewpoint=LAT,LNG
  storefront_visible,      // ทีมเปิด Street View หรือรูปใน Maps แล้วเห็นหน้าร้านจริง
  checked_by, checked_at   // ชื่อคนตรวจ + วันที่
}
photos: [{ file, kind: 'storefront'|'sign'|'interior'|'signature_dish'|'product', credit, license, source_url }]
```
- **ร้านต้องมีรูปอย่างน้อย 3 ภาพ:** หน้าร้านที่เห็นป้ายชื่อ, ภายในร้าน หรือบรรยากาศ, เมนูเด่น หรือสินค้าเด่น
- **แหล่งรูปที่อนุญาต:** ทีมถ่ายเอง, เจ้าของร้านให้มา, หรือ Wikimedia Commons ที่สัญญาอนุญาตเปิดให้ใช้ (บันทึก author, license และ source_url ทุกภาพ)
- **ห้ามดึงรูปจาก Google Maps, Wongnai หรือ Facebook** เพราะผิดเงื่อนไขการใช้และละเมิดลิขสิทธิ์ → ใช้ปุ่ม "ดูหน้าร้านใน Google Maps" และ "ดู Street View" ที่เปิด `maps_url` / `streetview_url` แทน
- **โหมดนักท่องเที่ยวแสดงเฉพาะที่ที่ `verified: true`:** ที่ยังไม่ผ่านให้เห็นเฉพาะในโหมดผู้บริหาร พร้อมป้าย "รอตรวจ"
- **สร้าง `scripts/verify-places.js` (สั่งรันด้วย `npm run verify:places`):**
  - ตรวจว่าทุกที่มีฟิลด์ครบ
  - ไฟล์รูปมีอยู่จริง
  - พิกัดอยู่ในกรอบตัวเมืองพิษณุโลก
  - ร้านมีรูปอย่างน้อย 3 ภาพ
  - พิมพ์ลิงก์ Maps และ Street View ของทุกที่ออกมาให้ทีมกดตรวจทีละที่
- **ร้านที่ยังไม่มีหลักฐานว่ามีอยู่จริง:** ผมค้นแล้วไม่พบหลักฐานของ "จุกไก่ไทย", "ก๋วยเตี๋ยวไก่ป้าล้อม" และ "ผัดไทยป้าถนอม" ในพิษณุโลก → ตั้งเป็น `verified: false` ไว้ก่อน แล้วถามผมว่าจะแทนด้วยร้านไหน
- **ร้านตัวเลือกที่มีบทความรีวิวยืนยัน** (ทีมต้องเช็กว่ายังเปิดอยู่และปักหมุดเอง): ก๋วยเตี๋ยวห้อยขาริมน่าน (ถนนพญาเสือ · ใน seed เขียนว่า "ซอยพุทธบูชา" ต้องเช็กว่าที่ไหนถูก), ขนมจีนต้นก้ามปู (ถนนสีหราชเดโชชัย), แอ๊ดผัดไทยและไอติมเจริญผล (ตลาดเจริญผล), โรงแรมชินะปุระ
- **ห้ามแต่งพิกัด:** พิกัดทุกจุดมาจากที่ทีมกดหมุดใน Google Maps เท่านั้น

# R3: ปุ่มเต็มจอที่แผนที่ 3 มิติ
- **ตำแหน่งปุ่ม:** มุมขวาบนของ `#map-stage` ใช้ไอคอนขยาย/ย่อ · `aria-label` เปลี่ยนตามสถานะ ("เปิดเต็มจอ" / "ออกจากเต็มจอ") · ขนาดอย่างน้อย 44×44px
- **วิธีเปิดเต็มจอ:** ใช้ `requestFullscreen()` กับ `#map-stage` เพื่อให้ป้ายชื่อใน `#map-labels` ตามเข้าไปด้วย
- **iPhone (Safari):** สั่งเต็มจอกับ div ไม่ได้ → ใช้โหมดสำรองที่ตั้ง CSS เป็น `position: fixed; inset: 0; height: 100dvh` แทน
- **เมื่อสลับโหมด:** ฟังทั้ง `fullscreenchange` และ `ResizeObserver` แล้วปรับขนาด renderer กับ camera aspect ให้ถูก · กด Esc หรือปุ่มเดิมเพื่อออกได้ · ระหว่างเต็มจอให้ปุ่มกรองหมวดและการ์ดรายละเอียดยังใช้ได้
- **ทดสอบ:** Chrome เดสก์ท็อป, Chrome Android และ Safari iPhone (หรือจำลองที่ 390px)

   - ใส่เครดิต "© OpenStreetMap contributors (ODbL)" ในหน้า credits
   - ถ้าเครื่องต่อ Overpass ไม่ได้ ให้บอกผม ทีมจะจดพิกัดเส้นแม่น้ำ 15–20 จุดจาก Google Maps มาให้แทน
2. **เช็กฝั่งแม่น้ำอัตโนมัติ:** เขียนเทสต์ที่ตรวจว่าแต่ละสถานที่อยู่ฝั่งเดียวกับในแผนที่จริง (เทียบตำแหน่งกับเส้นแม่น้ำ)
3. **ปั้นโมเดลจากภาพอ้างอิงจริง ไม่ใช่จากความจำ:**
   - ดาวน์โหลดภาพอ้างอิงจาก Wikimedia Commons (สถานที่ละ 2–3 ภาพ เก็บที่ `docs/ref/`)
   - **เปิดดูภาพด้วยตัวเอง** แล้วเขียนรายการลักษณะเด่นที่มองเห็นลง `docs/ref/NOTES.md` ก่อนเขียนโค้ดโมเดล
   - ลักษณะที่ต้องมี: รูปทรงอาคารหลัก, จำนวนชั้นหลังคา, สี, วัสดุ, ทิศที่ด้านหน้าหันไป, ขนาดเทียบกับอาคารรอบข้าง
   - ห้ามเติมรายละเอียดที่ไม่เห็นในภาพ
4. **ลำดับความละเอียด:** ทำวัดใหญ่ (พระปรางค์ประธานกับวิหาร) และพระราชวังจันทร์ให้ละเอียดที่สุดก่อน แล้วค่อยทำวัดราชบูรณะ วัดนางพญา และศาลหลักเมือง (`buildCityPillar` ตอนนี้เป็นกล่องไขว้กับกรวย 4 ชั้น ต้องทำใหม่ตามภาพอ้างอิง)
5. **ความสมจริงของฉาก:** ขนาดโมเดลเทียบกันต้องสมเหตุสมผล · โรงแรมสูงตามจำนวนชั้นจริงโดยประมาณ (ดูจากภาพ) · ทิศของด้านหน้าอาคารถูกต้อง
6. **งบประสิทธิภาพ:**
   - รวมทั้งฉากไม่เกินประมาณ 150,000 สามเหลี่ยม
   - ใช้ InstancedMesh กับต้นไม้และบ้าน · รวม geometry ที่ใช้วัสดุเดียวกัน
   - เป้าความลื่น: 60fps บนโน้ตบุ๊กทั่วไป และไม่ต่ำกว่า 30fps บนมือถือ
   - เมื่อผู้ใช้เปิด `prefers-reduced-motion` ให้ปิดแอนิเมชัน
7. **บอกผู้ใช้ตรงๆ เรื่องมาตราส่วน:** `gpsTo3D` ย่อระยะส่วนนอกเมือง ให้ใส่หมายเหตุเล็กๆ ใต้แผนที่ว่า "ระยะนอกย่านริมน่านถูกย่อ เพื่อให้เห็นทั้งเมืองในจอเดียว"

# R7: แถบด้านบนและแถบเลือกโหมด จัดระยะและสัดส่วนใหม่
เป้าหมาย: ทุกวัยใช้ง่าย ดูทันสมัยแบบยุค AI แต่ไม่ดูเป็นแม่แบบสำเร็จรูป และไม่ตกยุคเร็ว

**ระบบระยะห่าง:**
- ใช้ระยะเป็นทวีคูณของ 8px (4/8/12/16/24/32/48)
- ปุ่มและแท็บสูงเท่ากันทั้งแถว (44px บนมือถือ, 40–44px บนเดสก์ท็อป)
- มุมโค้งใช้ชุดเดียว (12px สำหรับปุ่ม, 16px สำหรับการ์ด)

**แถวที่ 1 (header):**
- ซ้าย: โลโก้กับชื่อ (ป้าย "v2.2" ให้เล็กลง หรือย้ายไปไว้ใน footer)
- กลาง: เมนู 3 หน้า
- ขวา: กลุ่มปุ่ม ธีม · คูปอง · ตะกร้า เว้นระยะเท่ากัน
- ปุ่มธีมเปลี่ยนเป็นไอคอนเดียวที่สลับได้ ไม่ต้องเขียน "สว่าง / มืด"

**แถวที่ 2 (เลือกโหมด):**
- เปลี่ยนเป็น segmented control 3 ช่อง กว้างเท่ากัน มีไอคอนกับคำไทยสั้นๆ: "นักท่องเที่ยว" · "ร้านและโรงแรม" · "ผู้บริหาร"
- ตัดวงเล็บภาษาอังกฤษ (Tourist View ฯลฯ) ออก เพราะมีปุ่มเลือกภาษาอยู่แล้ว

**แถวที่ 3 (ชิปคุณสมบัติ):** ตอนนี้ยาวเกินและแน่นเกินไป ให้ย้ายไปเป็นแถบเครื่องมือของแผนที่ หรือย่อเหลือไม่เกิน 3 ชิปที่ใช้กดได้จริง (ชิปที่กดไม่ได้ให้ตัดทิ้ง)

**มือถือ 390px:**
- เมนูหน้าเว็บย้ายเข้าเมนูแฮมเบอร์เกอร์
- แถวเลือกโหมดแสดงแค่ไอคอนกับคำสั้น ห้ามมีการเลื่อนจอแนวนอน

**อ่านง่ายทุกวัย:**
- ตัวหนังสือเนื้อหาอย่างน้อย 16px
- สีตัวหนังสือตัดกับพื้นตามมาตรฐาน WCAG AA ทั้งธีมสว่างและธีมมืด
- เห็นกรอบโฟกัสชัดเมื่อใช้คีย์บอร์ด
- ไม่มีแอนิเมชันที่ขยับเองนาน

**ตรวจผล:** ใช้ Playwright ถ่ายภาพ header ที่ 390, 768 และ 1440px ทั้งธีมสว่างและธีมมืด เก็บไว้ที่ `docs/screens/` แล้วเปิดดูเองก่อนบอกว่าเสร็จ

# R8: ลดข้อความให้เหลือแค่ใจความสำคัญ
**กติกาข้อความหน้าเว็บ:**
- หัวข้อไม่เกิน 8 คำ
- คำอธิบายใต้หัวข้อไม่เกิน 1 ประโยค
- การ์ดไม่เกิน 2 บรรทัด
- ปุ่มใช้คำกริยาสั้นๆ
- คำเทคนิค (SQLite, ≥48px, OWASP, CSP, Rate Limit) ห้ามอยู่ในหน้าที่ผู้ใช้ทั่วไปเห็น ให้อยู่ในหน้า credits เท่านั้น

**ข้อมูลโบราณสถาน:**
- แสดง summary 1 ประโยค (ภาษาไทยไม่เกินประมาณ 120 ตัวอักษร) + highlights 3 ข้อ
- ส่วน sections เดิมย้ายไปไว้ใต้ปุ่ม "อ่านเพิ่ม" ที่กดเปิดปิดได้
- แก้ภาษาไทยให้สั้นก่อน แล้วค่อยปรับอีก 5 ภาษาให้ความหมายตรงกัน (ห้ามปล่อยให้ภาษาอื่นยาวกว่าภาษาไทยมาก)

**ข้อความที่ใช้แทนของเดิม** (แก้ได้ แต่ต้องสั้นเท่านี้):
- หัวหน้าแรก: "เที่ยวพิษณุโลก เห็นทั้งเมืองใน 3 มิติ"
- คำอธิบาย: "ดูวัด วัง ร้านอร่อย และที่พักบนแผนที่จริง สั่งอาหารและจองได้ในที่เดียว 6 ภาษา"
- การ์ดนักท่องเที่ยว: "ดูแผนที่ ฟังเรื่องเล่า สั่งอาหาร" → ปุ่ม "เริ่มเที่ยว"
- การ์ดร้านและโรงแรม: "รับออเดอร์ จัดการเมนู ดูยอดขาย" → ปุ่ม "เข้าโหมดร้าน"
- การ์ดผู้บริหาร: "ดูรายได้ 4 ช่องทาง และจุดคุ้มทุน" → ปุ่ม "ดูแดชบอร์ด"
- แถบตัวเลข: "สถานที่บนแผนที่ [จำนวนจริง]" · "ร้านที่ยืนยันแล้ว [จำนวนจริง]" · "ภาษา 6"
- หัวข้อแผนที่: "แผนที่ 3 มิติ พิษณุโลก" (เอาคำว่า "อ้างอิงพิกัด GPS จริงจังหวัด…" ออก แล้วใส่เป็นหมายเหตุเล็กใต้แผนที่แทน)
- ก่อนเปลี่ยน ให้แสดงตารางข้อความเดิมเทียบข้อความใหม่ของทุกหน้าให้ผมดูก่อน
