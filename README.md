# PHITLOK NEXUS

แพลตฟอร์ม **3D Heritage & AI Vision Commerce** สำหรับจังหวัดพิษณุโลก — เชื่อมวัดพระศรีรัตนมหาธาตุวรมหาวิหาร (วัดใหญ่) และพระราชวังจันทน์ เข้ากับรายได้ของร้านค้าริมแม่น้ำน่าน

All for One University 2569 · สาย Software for Business & Tourism ("Make Me Money")

## เริ่มใช้งาน

ต้องใช้ Node.js 22.13 ขึ้นไป (ใช้ `node:sqlite` ที่มากับ Node ไม่ต้องคอมไพล์ native module)

```bash
npm install
npm start          # http://localhost:3000
npm test           # smoke test 22 ข้อ บนฐานข้อมูลชั่วคราว
npm run reset-db   # ลบฐานข้อมูลเพื่อ seed ใหม่ตอนเปิดครั้งถัดไป
```

Docker:

```bash
docker build -t phitlok-nexus .
docker run -p 3000:3000 -v phitlok-data:/app/data -e GEMINI_API_KEY=... phitlok-nexus
```

ตัวแปรสภาพแวดล้อมทั้งหมดอยู่ใน `.env.example` — **ไม่มีตัวไหนบังคับ** ระบบทำงานครบทุกฟีเจอร์โดยไม่ต้องมี API key

## เส้นทางทดสอบสำหรับกรรมการ (ประมาณ 3 นาที)

1. **แผนที่ 3D** → กด "ซูมไปที่วัดใหญ่" / "ซูมไปที่พระราชวังจันทน์" / "ซูมไปที่โซนก๋วยเตี๋ยวห้อยขา" กล้องจะเคลื่อนไปและเปิดการ์ดข้อมูล
2. **AI Smart Lens โหมด A** → Preset 1 → อ่านประวัติ 4 ภาษา → "🔊 ฟังเสียงบรรยาย" → กล่องรางวัลสีทองปลดล็อกคูปอง 15%
3. กด "สั่งอาหารที่ร้านก๋วยเตี๋ยวห้อยขา" → กรอง "ไร้ถั่วลิสง" → ใส่ตะกร้า → ดูใบสั่งอาหารสองภาษา → ชำระด้วย QR พร้อมเพย์ → "ยืนยันการชำระเงินสำเร็จ (โหมดสาธิต)"
4. สลับเป็น **มุมมองเจ้าของร้าน** (แถบลอยมุมขวาล่าง) → เห็นออเดอร์ใหม่พร้อมคำเตือนแพ้ถั่วตัวใหญ่ → กดเปลี่ยนสถานะ
5. ซื้อ **VIP Pass 99฿** → ปลดล็อกเสียงบรรยายฉบับเต็ม + คูปอง 500฿
6. สมัคร **Pro Merchant 199฿** (ต้องติ๊ก PDPA) → หมุดร้านใหม่ขึ้นแผนที่ 3D ทันที
7. **มุมมองผู้บริหาร** → ตัวเลขรายได้ 3 ช่องทางเพิ่มขึ้นจริงใน SQLite → เลื่อน Slider / กด "ต้นทุนเซิร์ฟเวอร์และ API เพิ่มขึ้น 2 เท่า" เพื่อดูจุดคุ้มทุน

### API

| Method | Path | หน้าที่ |
|---|---|---|
| GET | `/api/init-data` | landmarks, merchants, เมนู, สถานะผู้เยี่ยมชม |
| POST | `/api/scan-heritage` | OCR ป้าย (preset หรือรูป) → RAG → 4 ภาษา + ตราประทับ/คูปอง |
| POST | `/api/scan-menu` | OCR เมนู → Digital Menu 4 ภาษา + allergen tags |
| POST | `/api/quote` | คำนวณราคาตะกร้า (ไม่บันทึก) |
| POST | `/api/checkout` | สร้างรายการชำระ + QR พร้อมเพย์ (`vip_pass` / `order` / `saas`) |
| POST | `/api/checkout/:id/confirm` | ยืนยันการชำระ (โหมดสาธิต) → บันทึกธุรกรรม |
| GET | `/api/metrics` | รายได้ 3 ช่องทาง, รายวัน 14 วัน, ธุรกรรมล่าสุด |
| GET | `/api/audio-guide/:id` | สคริปต์เสียงบรรยาย (ฉบับเต็มต้องมี VIP — ตรวจฝั่งเซิร์ฟเวอร์) |
| GET | `/api/merchants/:id/dashboard` | ออเดอร์และยอดขายของร้าน |
| POST | `/api/orders/:id/status` | เปลี่ยนสถานะออเดอร์ |
| POST | `/api/merchants/:id/menu/publish` | เผยแพร่เมนูที่สแกนด้วย AI |

ทุก API (ยกเว้น merchant console และ `/api/metrics`) ต้องส่ง header `x-visitor-id` (UUID ที่เบราว์เซอร์สร้างและเก็บไว้)

## AI และโหมดสำรอง

- **มี `GEMINI_API_KEY`** — รูปที่อัปโหลดจะส่งให้ Gemini อ่านตัวอักษร (OCR) จากนั้นระบบ *ค้นคืนข้อมูลประวัติศาสตร์จากฐานข้อมูลที่ตรวจสอบแล้ว* ไม่ให้ AI แต่งเนื้อหาเอง
- **ไม่มี key / เกินโควตา (429) / timeout** — ตอบกลับทันทีด้วยข้อมูลสำรอง และหยุดเรียก Gemini 60 วินาที (circuit breaker) เพื่อไม่ให้กรรมการต้องรอ
  - ป้ายที่อัปโหลด: ให้ผู้ใช้เลือกสถานที่ แล้วแสดงข้อมูลที่ตรวจสอบแล้ว
  - เมนูที่อัปโหลด: แสดง "เทมเพลตเมนูยอดนิยม" **พร้อมป้ายบอกชัดเจน** ว่าไม่ใช่ข้อความจากรูป
- ปุ่ม Preset 1–3 ใช้ข้อมูลที่ตรวจสอบแล้วเสมอ จึงทำงานเหมือนกันทุกสถานการณ์

## ความปลอดภัยและการปฏิบัติตามกฎหมาย

- Helmet: CSP (`default-src 'self'`, สคริปต์เฉพาะ jsDelivr/unpkg สำหรับ Three.js), `X-Content-Type-Options: nosniff`, `frame-ancestors 'none'`
- Rate limit: API ทั่วไป 300/นาที, สแกน 40/นาที, ชำระเงิน 40/นาที ต่อ IP
- อัปโหลด: ≤ 5MB, เฉพาะ .jpg/.png/.webp และ**ตรวจ magic bytes** ของไฟล์จริง
- ราคา/ส่วนลด/ค่าธรรมเนียม: คำนวณจากฐานข้อมูลเสมอ client ส่งได้แค่ ID + จำนวน (มี test ยืนยันว่าราคาที่ปลอมมาไม่มีผล)
- PDPA: ประกาศความเป็นส่วนตัวในฟอร์มสมัครร้าน, บังคับ consent ทั้งฝั่ง client และ server, เบอร์โทรไม่ถูกส่งออกทาง API สาธารณะ
- รูปแบบธุรกิจ: Digital SaaS & Marketing Affiliate — ค่าอาหารโอนเข้าพร้อมเพย์ของร้านโดยตรง แพลตฟอร์มไม่ถือเงินลูกค้า

### ข้อจำกัดที่ควรรู้ (เวอร์ชันสาธิต)

- Merchant console และการเปลี่ยนสถานะออเดอร์**ไม่มีระบบล็อกอิน** เพราะออกแบบให้กรรมการสลับบทบาทได้ทันที — ก่อนใช้งานจริงต้องเพิ่ม authentication
- QR พร้อมเพย์ชี้ไปยังบัญชีสาธิต (`0000000000`) และการยืนยันการชำระเป็นปุ่มสาธิต — ใช้งานจริงต้องตั้ง `PROMPTPAY_ID` และเชื่อม webhook ยืนยันยอดจากธนาคาร
- เสียงบรรยายใช้ Web Speech API ของอุปกรณ์ คุณภาพเสียงภาษาไทย/จีน/เกาหลีขึ้นกับเสียงที่ติดตั้งในเครื่อง

## ข้อมูลประวัติศาสตร์

เรียบเรียงจากแหล่งข้อมูลสาธารณะ ข้อเท็จจริงหลักที่ใช้: พระพุทธชินราชสร้างราว พ.ศ. 1900 สมัยพระมหาธรรมราชาที่ 1 (พญาลิไท), บานประตูประดับมุก พ.ศ. 2299 สมัยสมเด็จพระเจ้าอยู่หัวบรมโกศ, รัชกาลที่ 5 โปรดเกล้าฯ ให้หล่อพระพุทธชินราชจำลองไปวัดเบญจมบพิตร พ.ศ. 2444, สมเด็จพระนเรศวรฯ เสด็จพระราชสมภพที่พระราชวังจันทน์ พ.ศ. 2098, กรมศิลปากรขุดแต่งพระราชวังจันทน์ตามมติ ครม. พ.ศ. 2545 พื้นที่ราว 128 ไร่ ควรตรวจทานกับกรมศิลปากร/วัดก่อนใช้งานเชิงพาณิชย์
